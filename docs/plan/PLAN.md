## 2. 기능 목록

### 첫 버전 (v1)

**보유 목록 보기·찾기**
- 표 한 줄에 게임 하나: 제목, 장르, 인원, 시간, 정가, 개수, 해봤음, 별점
- 열 머리를 누르면 정렬
- 찾기·거르기
  - 제목·제작사 글자 검색
  - 장르(보드게임 / 머더미스터리)
  - **"N명이 할 수 있는 게임"** (예: 5 입력 → 2-6인, 5인, 5+gm 등이 나옴)
  - 최대 시간 (예: 60분 이하)
  - 해봤음 / 안 해봄
  - **빈칸 있는 게임만** (인원·시간·가격이 빈 게임을 채울 때 쓴다)
- 맨 위 요약: 총 게임 수, 장르별 수, 안 해본 게임 수

**화면에서 고치기**
- 표에서 바로: 개수, 해봤음 체크, 별점
- 게임 상세 창에서: 나머지 전부
  - 게임 정보: 제목, 인원, 시간, 정가, 제작사, 장르, 판매 링크
  - 내 정보: 별점, 후기, 메모, 구입 정보
- 인원 입력은 고정 / 범위 / GM 세 가지에서 고른다
- 게임 추가와 삭제. 삭제 전에는 확인 창을 띄운다

**엑셀로 한꺼번에 편집**
- [엑셀 내려받기] → 엑셀에서 고치기 → [엑셀 올리기]
- 올리면 **바뀔 내용을 먼저 보여준다**: 추가 / 변경 / 그대로. [적용]을 눌러야 저장한다
- 빈칸은 "그대로 두기"로 처리한다. 지우려면 정해진 표시를 쓴다 (규칙은 엑셀 안내 시트에 적는다)
- 행은 **게임 ID**로 맞춘다. 새 행은 ID 칸을 비워 두면 새 게임으로 추가한다
- 숫자 칸은 검증하고, 잘못된 값은 행 번호와 함께 알려 준다
- 고칠 수 있는 칸과 없는 칸을 색으로 나누고, 안내 시트를 넣는다

**데이터 안전장치**
- 저장할 때마다 백업을 남긴다 (`data/backups/`, 최근 N개 보관)
- 파일 쓰기는 원자적으로 한다. 임시 파일에 쓴 뒤 바꿔치기해서, 중간에 꺼져도 파일이 깨지지 않는다

### 나중에 (v1에서는 하지 않음, 순서 미정)

- 플레이 기록 (언제, 누구와)
- 다음 게임 추천 (인원·시간·멤버 → 아무도 안 해본 게임). 플레이 기록이 먼저 필요하다
- 구매 희망 목록
- 휴대폰에서 보기 (같은 와이파이)
- 스마트스토어 가격 다시 확인 (자동 접근이 막혀 있어 방법부터 찾아야 한다)

### 하지 않음

- 회원·로그인·권한, 동아리, 회비, 모임, 채팅, 인터넷 배포
  - 2026-10-09: 동아리 회비·게시판·관리자 **메뉴 자리**는 만들었다 ([decisions/0002](../decisions/0002-sidebar-menu.md)). 로그인·배포는 하지 않고 혼자 쓰는 장부로 유지한다 ([questions.md](../questions.md) 8번)
- `catalog.json`의 보유하지 않은 게임 (필요하면 옛 저장소에서 다시 뽑는다)

## 3. 데이터 설계

### 저장 위치

- `data/collection.json`: 보유 게임 목록. 게임 하나에 레코드 하나
- `data/backups/`: 저장할 때마다 남기는 복사본
- `data/`는 git에 올리지 않는다 (개인 데이터)
- 위치는 환경변수로 바꿀 수 있게 한다. 테스트는 임시 폴더를 쓴다

### 레코드 모양 (안)

옛 레코드를 바탕으로 **게임 정보**와 **내 정보**를 나눈다. 크롤링에만 쓰던 칸은 정리한다.

```jsonc
{
  "id": "manual:604d3b5a",            // 옛 game_id 그대로. 바꾸지 않는다
  "title": "딕싯",
  "genres": ["보드게임"],              // 보드게임 / 머더미스터리, 0~2개
  "player_count": ["3-8인"],          // 옛 표기 규칙 그대로. 빈 배열 = 모름
  "play_time_minutes": 30,            // null = 모름
  "price": 59000,                     // 할인 전 정가(원). null = 모름
  "publisher": "코리아보드게임즈",
  "sale_link": "https://...",
  "images": [],
  "tags": [],
  "source": "manual",                 // 어디서 온 정보인지 (참고용)
  "mine": {
    "quantity": 1,                    // 새 항목. 기본 1. 카탄 3, 스플렌더 2
    "played": false,                  // 새 항목. 내가 해봤는지
    "rating": null,                   // 1~5
    "review": null,
    "notes": null,
    "added_at": "2026-10-08T...",
    "purchase": {                     // 새 항목. 모두 비워 둘 수 있다
      "date": null,                   // 구입일
      "paid": null,                   // 구매가격(원). 정가(price)와 따로
      "shop": null                    // 산 곳
    }
  }
}
```

**옛 칸 처리 (안: 옮길 때 미리보기로 보여드리고 확인받음)**

| 처리 | 칸 |
|---|---|
| 그대로 둔다 | 제목, 인원, 시간, 가격, 제작사, 장르, 태그, 판매 링크, 이미지, 출처 |
| 기타 정보로 묶어 둔다 | `sale_status`, `funding_*`, `crawled_at`, `release_date`, `creator`, `difficulty`, `sellers`, `review_*`, `rating_avg`. 지우지 않고 `extra`에 보관해서 화면에서 참고용으로만 보여 준다 |

### 옛 데이터 옮기기 (한 번만)

1. `handoff/collection.json`(99개)을 새 모양으로 바꾼다
2. 처음 값
   - 개수: 모두 1, 카탄만 3, 스플렌더만 2
   - 해봤음: "보통의 머더미스터리"만 true, 나머지는 false
3. 바뀔 내용을 먼저 보여 드리고, 확인을 받은 뒤 `data/collection.json`에 저장한다
4. 옮긴 뒤 검사한다: 99개인지, ID가 그대로인지, 빈칸 수(인원 12, 시간 20, 가격 28)가 같은지

> "해봤음"을 처음에 더 많이 채우고 싶으면, 옮긴 뒤 엑셀로 한꺼번에 체크하면 된다.

```
├──────────────────────────────────────────────────────────────┤
│ 제목▲      │장르│인원 │시간 │정가   │개수│해봄│별점 │          │
│ 딕싯       │보드│3-8인│30분 │59,000 │ 1  │ ☑ │★★★★☆│          │
│ 망령 열차  │머더│5인  │120분│   —   │ 1  │ ☐ │     │          │

```

1. **목록 화면** (메인): 위 그림과 같다. 제목을 누르면 상세 창이 열린다. 빈칸은 "—"로 흐리게 표시한다.
2. **게임 상세·편집 창**
   - 게임 정보 / 내 정보(별점·후기·메모·구입 정보) / 기타 정보(옛 칸, 읽기 전용)
   - [저장] [삭제]
   - 이미지가 있으면 보여 준다
3. **엑셀 올리기 미리보기 창**
   - 추가 N / 변경 N / 오류 N 요약
   - 변경은 게임별로 "칸: 이전 → 새 값"으로 보여 준다
   - [적용] [취소]

## 5. 기술 구성

| 부분 | 선택 | 이유 |
|---|---|---|
| 서버 | Python 3 + **FastAPI** | 옛 코드(인원 해석·엑셀)를 참고하기 쉽다 |
| 저장 | **JSON 파일** + 원자적 쓰기 + 백업 | 게임 99개에는 충분하다. 파일을 직접 열어 볼 수 있다 |
| 엑셀 | **openpyxl** | 옛 앱에서 검증한 방식 |
| 화면 | **React + TypeScript + Vite** | 표 정렬·거르기·바로 고치기를 매끄럽게 만들 수 있다 |
| 실행 | 화면을 빌드해서 FastAPI가 함께 띄운다. **`start.bat` 하나**로 서버를 켜고 브라우저를 연다 | 평소에는 서버 하나만 쓴다 |
| 테스트 | pytest(서버), Vitest(화면 로직) | 테스트는 임시 데이터 폴더를 쓰고, 실데이터가 바뀌면 실패하게 한다 |
| 버전 관리 | git, 로컬 커밋만 한다 (push는 요청할 때만) | |

- 서버는 `127.0.0.1`에만 연다. 같은 와이파이의 다른 기기에서도 접속할 수 없다.
- 개발 중에는 Vite 개발 서버(화면)와 FastAPI(`--reload`)를 따로 띄운다.

## 6. 진행 순서

각 단계는 **테스트 통과 + 실제 화면 확인**으로 끝낸다. 확인하지 못한 것은 "확인 못 함"으로 적는다.

| 단계 | 할 일 | 끝났다는 기준 |
|---|---|---|
| 0. 준비 | git 시작, 폴더 구조, `.gitignore`(data 제외), 파이썬 가상환경·npm 설정 | 빈 서버와 빈 화면이 뜬다 |
| 1. 저장소·옮기기 | JSON 저장(원자적 쓰기·백업), 인원 해석, 옮기기 스크립트 | 미리보기를 확인받고 적용한다. 99개, 빈칸 수, ID가 같은지 검사를 통과한다 |
| 2. 목록 보기 | 목록 API, 표 화면, 정렬, 검색·거르기(N명 가능 포함), 요약 | 실제 화면에서 거르기 결과가 맞다 |
| 3. 화면에서 고치기 | 표에서 바로 고치기(개수·해봄·별점), 상세 창, 추가·삭제 | 고친 값이 파일에 저장되고 백업이 생긴다 |
| 4. 엑셀 | 내려받기, 올리기 → 미리보기 → 적용, 오류 안내 | 엑셀을 내려받아 고친 뒤 다시 올리면 정확히 반영된다 |
| 5. 마무리 | `start.bat`, 사용법 짧게(README), 빈칸 채우기 1회 (엑셀) | 바로가기로 켜서 평소처럼 쓸 수 있다 |

v1 뒤에 더한 것: 표에서 바로 고치는 칸 늘림(제작사·인원·시간·정가·구매가격), 제작사별 거르기, 장르 탭,
스토어 바로가기 사이드바(`data/stores.json`. 네이버 스마트스토어는 자동 수집을 막아서 상품 목록은 가져오지 않고, 새 탭으로 연다).

## 7. 지켜야 할 규칙 (인수인계에서 이어짐)

- **데이터 변경:** 미리보기 → 확인 → 백업 → 적용
- **게임 정보:** 인원·시간·가격은 출처에서 확인한 값만 넣는다. 모르면 비운다. 가격은 할인 전 정가다
- **ID:** 게임 ID는 바꾸지 않는다
- **제목:** 새로 정리한 제목은 사용자 확인을 받는다
- **동시 수정:** 사용자가 작업 중에도 앱을 쓸 수 있다. 백업에서 되돌리기 전에 지금 데이터와 비교한다
- **한글 출력:** 파이썬 출력이 깨지면 `PYTHONIOENCODING=utf-8`을 붙인다

## 8. 화면 확인 방법
