# v3 대시보드 마을 미니게임

작성: 2026-10-09 · 상태: **진행 중** (2026-10-09 1단계 바탕, 2단계 밭 완료)

## 왜

대시보드는 아직 '준비 중'이다. 이 자리를 업무 화면이 아니라 **심심풀이로 즐기는 마을 미니게임**으로 만든다.
컨셉은 픽셀아트 마을이다. 위에 자원 줄을 두고, 건물을 누르거나 걸어가서 들어간다.
화면 규칙 예외와 기술 선택은 [decisions/0003](../decisions/0003-dashboard-village.md)에 적는다.

## 정한 것 (2026-10-09 사용자 답변)

| 항목 | 결정 |
|---|---|
| 구현 수준 | **2단계**: 타일 지도와 움직이는 캐릭터. 1단계(그림 한 장 + 클릭 영역)와 3단계(진짜 게임) 사이 |
| 건물 | 밭 · 집 · 상점 · 연구소 (4개) |
| 밭 | 자동으로 재화를 만든다. 작물에 레벨이 있다 (LV1, LV2, …) |
| 연구소 | 작물 레벨을 올린다 |
| 상점 | 뽑기. 가구 · 스킨 · 꾸미기 · 재화가 나온다. **처음에는 단순 뽑기로 만든다** (확률·중복 처리는 나중에 기획) |
| 집 | 들어가면 새 지도(집 안)로 바뀐다. 꾸미기를 하고, **내 보드게임이 책장에 책으로 꽂힌다** |
| 책장 | 책을 누르면 그 게임 정보를 보여 준다 |
| 꾸미기 | 칸에 맞춰 놓는다. 겹쳐 놓기도 된다. **뒤로 미룬다** |
| 스킨 | 캐릭터뿐 아니라 건물 그림도 바꿀 수 있다 |
| 움직임 | 키보드(방향키·WASD) 또는 마우스 클릭으로 그 자리까지 걸어간다 |
| 재화 | 코인 · 크리스탈 |
| 쌓이는 보상 한도 | 화면을 꺼 둔 동안 **12시간**까지 쌓인다. 나중에 24시간까지 늘릴 수 있다 |
| 저장 | **서버** (데이터 폴더) |
| 그림 | **Sprout Lands 기본판** (Cup Nooble, 무료·비상업, 16px). 칸 크기와 파일 이름을 고정해 나중에 다른 팩으로 갈아 끼울 수 있게 한다. 조사: [research/village-assets.md](../research/village-assets.md) |
| 글꼴 (기본값) | 마을 안에서만 **Galmuri** (SIL OFL 1.1, npm `galmuri`) |

## 설계

### 화면
- 앱 틀(상단바·사이드바)은 그대로 두고, 대시보드 본문을 마을이 채운다.
- 마을 지도와 캐릭터는 PixiJS 캔버스로 그린다. 지도는 Tiled로 만든 JSON을 불러온다.
- 자원 줄, 건물 패널(밭·연구소·상점), 아래 메뉴는 React와 HTML로 캔버스 위에 띄운다.
- 클릭 이동은 타일 칸 위에서 길을 찾는다(A*). 건물 문 앞에 닿거나 건물을 누르면 패널이 열린다.

### 서버
- 마을 상태는 보드게임 데이터와 **다른 파일**에 둔다 (예: `data/village.json`). 서로 망가뜨리지 않는다.
- 저장하는 것: 코인, 크리스탈, 작물 레벨, 마지막으로 거둔 시각, 가진 아이템, 입은 스킨, 캐릭터가 서 있던 칸, (나중에) 집 배치.
- 캐릭터 자리는 건물에 들어갈 때와 화면을 떠날 때 저장한다. 제자리면 쓰지 않는다 (저장할 때마다 백업이 생겨서).
- **밭 보상은 서버가 계산한다.** '마지막으로 거둔 시각'부터 흐른 시간으로 계산하고, 12시간이 넘으면 자른다.
- **뽑기 결과도 서버가 정한다.** 화면에서 정하면 조작할 수 있어서다.
- 데이터를 바꾸기 전에 백업하는 규칙은 다른 데이터와 같다.

### 책장
- 지금 게임 목록(`/api/games`)을 그대로 읽는다. 마을 상태에 게임 데이터를 복사하지 않는다.
- 책 등에는 장르 색을 쓴다(보드 이끼색, 머더 와인색). 누르면 그 게임 정보를 띄운다.

## 1단계에서 만든 것 (2026-10-09)

| 부분 | 파일 |
|---|---|
| 화면 | `frontend/src/pages/VillagePage.tsx` (패널·안내), `frontend/src/lib/village/scene.ts` (PixiJS 캔버스) |
| 계산 | `frontend/src/lib/village/tiled.ts` (지도 읽기), `path.ts` (A* 길찾기·부딪힘), 테스트 `village.test.ts` |
| 서버 | `backend/app/village.py`, `GET /api/village`, `PUT /api/village/player` |
| 그림 | `frontend/public/village/` (지도·타일셋·건물·캐릭터, 출처 `CREDITS.md`) |

- 화면 크기에 맞춰 2~4배 정수 배율로 키운다. 지도가 화면보다 크면 카메라가 캐릭터를 따라간다.
- 들어가기: 건물(또는 밭)을 누르면 문 앞까지 걸어가서 패널을 연다. 키보드로는 문 앞 칸에서 위로 걸으면 열린다.
- 마을 화면은 따로 불러온다 (PixiJS가 커서 다른 메뉴를 느리게 하지 않게).

## 2단계에서 만든 것 (2026-10-09)

- **계산은 서버가 한다** (`backend/app/village.py`의 `farm`·`harvest`)
  - 쌓인 코인 = 마지막으로 거둔 뒤 흐른 시간(최대 12시간) × 시간당 코인 (LV1 10 · LV2 25 · LV3 60, 임시 숫자)
  - 한도 안에서 거두면 코인 한 개가 되기 전 자투리 시간은 남긴다. 자주 거둬도 손해가 없다.
  - 한도를 넘겨서 거두면 넘긴 시간은 버리고 지금부터 다시 센다.
  - `GET /api/village`에 지금 시각 기준 `farm`(쌓인 코인·한도·시간당)과 `server_time`을 붙여 보낸다. 파일에는 저장하지 않는다.
  - `POST /api/village/harvest`: 거둘 것이 없으면 아무것도 바꾸지 않고 `harvested: 0`을 돌려준다.
- **화면** (`frontend/src/lib/village/farm.ts`, `VillagePage.tsx`)
  - 서버 시각과 이 컴퓨터 시각의 차이를 재 두고, 1초마다 쌓인 코인과 "가득 차기까지 N시간 M분"을 다시 센다.
  - 밭 패널: 작물 레벨, 시간당 코인, 쌓인 코인 막대, [거두기]. 거둘 것이 없으면 단추가 꺼진다.
  - 지도 왼쪽 위 자원 줄: 코인 · 크리스탈 (크리스탈은 4단계 뽑기에서 생긴다)
  - 지도의 작물은 한도의 1/4씩 찰 때마다 한 단계 자란다 (그림 4단계). 거두면 처음 모습으로 돌아간다.
- **아이콘:** 코인·크리스탈은 팩에 없어서 팩 팔레트 색으로 직접 찍었다 (`scripts/build_village_assets.py`의 `ICONS`).
- **나중에 3단계(연구소)에서 지킬 것:** 작물 레벨을 올리기 전에 쌓인 코인을 먼저 거두거나 옛 레벨로 정산해야 한다. 안 그러면 지난 시간까지 새 레벨로 계산된다.

## 지도 고치기

지도는 [Tiled](https://www.mapeditor.org/)로 연다: `frontend/public/village/maps/village.tmj`

- **층**
  - 바닥: `water` → `ground`(풀밭) → `soil`(밭흙) → `crops` → `fences` → `decor`
  - `buildings`: 오브젝트 층. 건물 그림과 밭 영역
  - `above`: 캐릭터보다 위에 그린다 (나무 윗부분)
  - `collision`: 걸을 수 없는 칸. 무엇이든 놓으면 막힌다. 화면에는 그리지 않는다
- **건물·밭 오브젝트**의 사용자 속성
  - `kind`: `farm` · `house` · `shop` · `lab`
  - `entryX`, `entryY`: 들어가는 칸 (문 바로 앞)
- **시작점:** `spawn`이라는 이름의 점 오브젝트. 저장된 자리가 없을 때 여기서 시작한다.
- 고친 뒤 `npm --prefix frontend test`를 돌리면 시작점에서 모든 문 앞까지 걸어갈 수 있는지 검사한다.
- 그림(타일셋·건물)을 다시 만들 때: 원본 팩을 `assets-src/village/sprout-lands/`에 두고 `python scripts/build_village_assets.py`를 실행한다. 지도는 덮어쓰지 않는다.
