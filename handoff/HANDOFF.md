# 인수인계: Danseo → 개인용 보드게임 사이트 (2026-10-08)

이 문서는 새 프로젝트를 진행하는 AI가 읽는다. 사용자는 이 문서를 직접 읽지 않는다.
같은 폴더의 데이터 파일과 함께 넘어간다.

---

## 1. 배경

- **Danseo:** 보드게임 동아리용 웹앱이다. 처음에 Gemini로 만들었다.
  - 구조: FastAPI + JSON 파일 DB + React/TS/Vite + Go 채팅 서버.
  - 기능: 회원, 동아리, 회비, 모임, 채팅, 보유 게임, 플레이 기록, 게임 검색. 여러 사람이 쓰는 서비스였다.
- **2026-10 재정비:** Claude가 재정비를 마쳤다. 테스트 352개 통과, 감사 항목 100% 처리.
- **새 방향:** 사용자는 이것을 서비스가 아니라 **본인 혼자 쓰는 개인용 사이트**로 완전히 개편하기로 했다. 그래서 새 프로젝트로 시작한다.
- **새 프로젝트의 목적과 기능은 아직 정하지 않았다.** 첫 단계로 사용자와 개편 계획(무엇을 할 사이트인지)을 세운다.
  - 사용자가 지나가며 언급한 후보: 보유 목록 관리, 플레이 기록, "누가 안 했지/다음에 할 게임" 추천, 구매 희망 목록, 엑셀로 한꺼번에 편집.
  - 이 후보들은 확정된 것이 아니다.

## 2. 사용자에 대해 (작업 방식)

- **언어:** 한국어로 답한다. 쉬운 말로, 결과부터 말한다. 기술 용어는 풀어 쓴다.
- **선택지 제시:** "추천대로 진행해줘"라고 자주 말한다. 선택지를 줄 때는 추천안을 첫 번째에 두고 이유를 짧게 단다.
- **질문 방식:** 확인이 필요한 질문은 **한 번에 하나씩** 묻는 것을 선호한다. 묻는 동안에도 다른 작업은 이어서 한다.
- **데이터 변경:** 늘 같은 패턴으로 한다.
  1. 바뀔 내용을 미리 보여준다.
  2. 확인을 받는다.
  3. 적용한다.
  4. 적용 전에 백업한다.
- **완료 기준:** 테스트 통과에 더해, 실제 화면에서 확인해야 완료다. 확인하지 못한 것은 "확인 못 함"이라고 분명히 말한다.
- **편집 방식:** 직접 편집할 때는 **엑셀로 한꺼번에** 하는 것을 좋아한다.
- **사실 확인:** 게임 정보(인원·시간·가격)는 추측하지 말고 출처에서 확인한 값만 쓴다. 모르면 비워 둔다.
- **환경:** Windows 11. PowerShell과 Git Bash를 둘 다 쓸 수 있다. 저장소는 `D:\github\`에 둔다.
- **git:** 커밋은 로컬에서 한다. push는 사용자가 요청할 때만 한다.

### 데이터 규칙 (재정비 때 정했고 사용자가 확인함)

- **ID:**
  - 크롤링한 게임: `naver:<스마트스토어 상품번호>`, `tumblbug:<프로젝트 slug>`
  - 직접 등록한 게임: `manual:` + md5(제목)의 앞 8자. 제목이 같으면 ID도 같다.
  - ID는 바꾸지 않는다. 엑셀 동기화도 ID로 행을 맞췄다.
- **인원 표기:**
  - 형식: `"4인"`, `"2-4인"`, `"5+gm"` (게임마스터가 필요한 게임).
  - 여러 표기는 하나로 합친다. 예: `["4-5인","4인용","5인용"]` → `["4-5인"]`
  - 이어지지 않는 인원은 따로 둔다. 예: `["2인","4인"]`
  - 해석·정규화 코드는 옛 저장소 `backend/app/services/players.py`에 있다. 그대로 가져다 쓰면 된다.
- **플레이 시간:** 출처가 범위(예: 45~60분)이면 보통 최댓값을 넣었다. 예외로 카탄은 사용자가 75분으로 정했다.
- **가격:**
  - 기준은 **할인 전 정가**다. 할인가는 판매처·날짜마다 달라서 쓰지 않았다.
  - 직접 등록 게임 약 40개: 2026-10-08 기준으로 코리아보드게임즈, 팝콘에듀, 보드엠, 예스24 등에서 확인했다. `sale_link`가 그 확인 페이지다.
  - 네이버 스마트스토어 게임 약 32개: **2026-05 크롤링 값 그대로이고, 다시 확인하지 못했다.**
- **장르:**
  - 사용자는 게임을 크게 **보드게임 / 머더미스터리**로 나눈다. 둘 다 해당할 수도 있다.
  - 현재 분포: 머더미스터리 67, 보드게임 32. 미분류는 0이다.
- **제목:**
  - 보유 게임 제목은 모두 정리했다. 쇼핑몰 문구와 스토어 이름을 빼고 게임 이름만 남겼다. 사용자가 확인했다.
    - 예: "망령 열차 언더독게임즈 보이지 않는 머더 미스터리 추리게임" → "망령 열차"
    - 제목에서 뺀 스토어 이름은 비어 있던 제작사 칸에 넣었다.
  - `catalog.json`에서 보유하지 않은 크롤링 게임은 쇼핑몰 제목 그대로라 지저분하다.
  - 새로 정리할 때도 정리한 제목은 반드시 사용자에게 확인받는다.

### 사용자가 확인해 준 사실 (다시 묻지 말 것)

- **같은 게임으로 확인된 것:**
  - 크라켄 = 노 터치 크라켄
  - 별장 = 머더 미스터리 미니: 별장 살인
  - 파라다이스 호텔 = 언더독 게임즈 "낙원주점" (Paraiso Hotel)
  - DOTS AND LINES = 에피소드: 결단
- **탁상탐정단:**
  - 갖고 있는 것은 "사신들의 진혼가"다. 레드스마일은 없다.
  - 사용자 요청으로 머더미스터리로 분류했다.
- **혈석류학원:** 부제 "소녀의 미소"가 맞다.
- **죽음을 잇는 저택:** 갖고 있는 것은 "죽음을 잇는 저택, 신전" (후디드)이다.
- **두 게임으로 나눈 것:**
  - 문어형님 세트 → 문어형님 타코야끼 조리사건 / 크림향 낭자한 만쥬의 죽음
  - 쿠와 쿠: 리포메이션
- **크라임 퍼즐:** 게임이 아니라 추리 퍼즐 책이지만 보유 목록에 넣는다.
- **<다니오><디어와이>:** 텀블벅 펀딩 하나였지만, 사용자 요청으로 "다니오"와 "디어와이" 두 게임으로 나눴다.
  - 세트 가격 76,000원은 한 게임 가격이 아니라서, 두 보유 항목의 메모로 옮겼다.
  - "디어와이"의 ID는 `manual:0d8a877a`이다.
- **같은 게임 여러 개:** 카탄 3개, 스플렌더 2개를 갖고 있다. 데이터에는 게임마다 한 줄씩만 있고, 개수는 아직 기록하지 않았다.
- **스플렌더:** 새 판본 정가 65,000원이 맞다.

## 5. 재정비 중 겪은 함정 (같은 실수 방지)

- **Windows 콘솔 한글:** 파이썬 출력이 깨지면 `PYTHONIOENCODING=utf-8`을 붙인다.
- **Write 도구:** 줄 끝 공백이 사라질 수 있다. 기존 파일을 문자열로 바꿀 때 주의한다.
- **React StrictMode:** 개발 모드에서 effect가 두 번 실행된다. 폼 초기값은 effect에서 넣지 말고 초기 state로 넣는다.
- **CSS transform 안의 모달:** `transform`이 걸린 부모 안의 고정 위치 모달은 갇힌다. 부모의 글자 스타일(예: `white-space: nowrap`)도 물려받는다. `createPortal(…, document.body)`로 띄운다.
- **Vite HMR:** 가끔 옛 모듈을 계속 쓴다. 화면이 코드와 다르면 파일을 touch하거나 새로고침한다.
- **백엔드 재시작:** 옛 `.claude/launch.json`의 백엔드는 `--reload` 없이 떠 있었다. 백엔드 코드를 바꾸면 재시작해야 반영된다.
- **테스트 격리:** 테스트는 임시 데이터 폴더를 써야 한다. 옛 저장소는 `conftest.py`에서 `DANSEO_DATA_DIR`을 임시 폴더로 바꾸고, 실데이터가 바뀌면 테스트를 실패시켰다. 같은 장치를 권한다.
- **사용자와 데이터 동시 수정:** 사용자는 작업 중에도 앱을 직접 쓴다. 실제로 2026-10-08 22:19~22:22에 게임 10개를 추가하고 굿즈 4개를 지웠다. 백업에서 복원하기 전에 지금 데이터와 비교해서, 사용자 변경을 덮어쓰지 않는다.
- **pydantic 모델:** 필드 이름 `date`가 `date` 타입을 가린다. `from datetime import date as Date`로 쓴다.
